## 简介

本文档介绍 AppTracker 的日志配置、崩溃诊断机制和常见问题的排查方法。

## 日志系统

### 日志框架

使用 `tracing` + `tracing_subscriber`：

```rust
tracing_subscriber::fmt()
    .with_env_filter(
        std::env::var("RUST_LOG")
            .unwrap_or_else(|_| "tracker_core=info,apptracker=info".to_string()),
    )
    .try_init()
    .ok();
```

### 日志级别配置

通过 `RUST_LOG` 环境变量控制：

```bash
# 默认级别
RUST_LOG=tracker_core=info,apptracker=info

# 调试模式（包含平台 API 调用详情）
RUST_LOG=tracker_core=debug

# 仅错误
RUST_LOG=tracker_core=error

# 全部调试
RUST_LOG=debug
```

### 关键日志点

| 模块 | 级别 | 内容 |
|------|------|------|
| agent | `debug` | 窗口查询失败 |
| agent | `warn` | supervised 任务正常退出 |
| agent | `error` | supervised 任务 panic |
| api | `error` | API 服务器停止 |
| api | `warn` | SSE 客户端 lagged |
| activity | `warn` | rdev 监听失败 |
| capture | `debug` | 截图失败 |
| platform | `warn` | PowerShell/osascript 超时 |
| platform | `debug` | 平台 API 查询失败 |

## 崩溃诊断

### Panic Hook

AppTracker 安装全局 panic hook，将崩溃信息写入 `~/.active_tracker/crash.log`：

```rust
pub fn install_panic_hook() {
    static ONCE: Once = Once::new();
    ONCE.call_once(|| {
        let prev = std::panic::take_hook();
        std::panic::set_hook(Box::new(move |info| {
            write_crash(info);
            prev(info);
        }));
    });
}
```

### 崩溃日志格式

```
==== panic @ ts=1719532800 thread=activity-listener ====
thread 'activity-listener' panicked at '...', src/activity.rs:42:5
backtrace:
   0: ...
   1: ...
```

### 崩溃日志位置

| 平台 | 路径 |
|------|------|
| Windows | `%USERPROFILE%\.active_tracker\crash.log` |
| macOS/Linux | `~/.active_tracker/crash.log` |

### Supervised 重启

关键任务（window_monitor、window_enrichment）panic 后会自动重启，重启信息记录在日志中：

```
ERROR worker=window_monitor attempt=1 worker panicked; restarting in 2s
```

## 常见问题

### 1. 端口被占用

**症状**：启动失败或连接不上

**排查**：

```bash
# 检查端口占用
netstat -ano | findstr :5007  # Windows
lsof -i :5007                 # macOS/Linux
```

**解决**：AppTracker 自动回退到 5008-5012，或在 UI 中修改 API 地址。

### 2. macOS 权限问题

**症状**：osascript 超时，窗口标题为空

**排查**：检查日志中的 `osascript timed out` 警告

**解决**：
1. 系统设置 > 隐私与安全性 > 辅助功能 > 添加 AppTracker
2. 系统设置 > 隐私与安全性 > 自动化 > 允许 AppTracker 控制 Finder 等

### 3. Linux Wayland 下无法获取窗口

**症状**：窗口标题为空，错误信息包含 "Wayland"

**解决**：使用 X11 会话，或接受 Wayland 的限制（/proc/fd 和 AT-SPI 仍可用）。

### 4. 浏览器扩展无法连接

**症状**：UI 显示"等待浏览器扩展连接"

**排查**：
1. 确认 AppTracker 已启动（`curl http://127.0.0.1:5007/api/v1/health`）
2. 确认 Token 已正确粘贴到扩展
3. 检查扩展图标 badge（绿色 = 已连接，红色 = 未连接）

**解决**：
1. 在扩展弹窗中重新粘贴 Token
2. 刷新扩展（Chrome: `chrome://extensions` -> 刷新按钮）

### 5. 截图失败

**症状**：截图区域显示空白

**排查**：检查日志中的 `screenshot capture failed` 调试信息

**可能原因**：
- 无显示器连接（远程桌面）
- 权限不足（macOS 需要屏幕录制权限）

### 6. 文档路径不准确

**症状**：显示的文档路径不是用户正在查看的文件

**排查**：
1. 在 UI 中查看文档的 `source` 和 `confidence` 字段
2. 低置信度（<0.5）的路径可能是噪声

**说明**：文档追踪依赖多种启发式方法，不可能 100% 准确。

## 调试技巧

### 1. 启用详细日志

```bash
RUST_LOG=tracker_core=debug npm run tauri dev
```

### 2. 测试 API

```bash
# 健康检查
curl http://127.0.0.1:5007/api/v1/health

# 快照
curl http://127.0.0.1:5007/api/v1/snapshot | jq

# 截图
curl http://127.0.0.1:5007/api/v1/screenshot -o screenshot.png
```

### 3. 测试 WebSocket

```javascript
const ws = new WebSocket('ws://127.0.0.1:5007/api/v1/ws');
ws.onmessage = (e) => console.log(JSON.parse(e.data));
ws.onopen = () => ws.send('snapshot');
```

### 4. 检查 Token

```bash
cat ~/.apptracker/token
```

### 5. 清理旧数据

```bash
# 删除 Token（下次启动会重新生成）
rm ~/.apptracker/token

# 删除 Shell 集成文件
rm -rf ~/.active_tracker/shells/

# 删除崩溃日志
rm ~/.active_tracker/crash.log
```
