## 简介

AppTracker 是一款专注于桌面活动上下文采集的开源工具。它不记录具体的应用内容（如文档正文、聊天消息），而是追踪"用户当前在看什么、在哪个目录、在浏览什么网页"这类元数据级别的活动信息。

## 项目背景

项目最初名为 Active Tracker，后更名为 AppTracker。核心动机是解决一个常见的工作痛点：在多任务切换频繁的工作场景中，用户常常忘记"刚才在做什么"——打开了哪些文件、终端在哪个目录、浏览器在看哪个页面。AppTracker 通过持续采集这些上下文信息，让用户能够随时查看当前工作全景。

## 目标用户

| 用户类型 | 典型需求 |
|---------|---------|
| 开发者 | 记录终端 cwd、编辑器打开的文件、浏览器文档页面 |
| 知识工作者 | 追踪 Office 文档、PDF、笔记应用的使用情况 |
| 效率分析爱好者 | 统计应用使用时间、键鼠活动模式 |
| 自动化工程师 | 基于桌面活动状态触发工作流 |

## 使用场景

### 场景一：工作上下文快照

开发者在多个终端、编辑器和浏览器之间频繁切换。通过 AppTracker 的 API 或 UI，可以随时查看当前全景：

```json
{
  "window": { "app_name": "Code", "window_title": "main.rs - AppTracker" },
  "terminal_context": { "shells": [{ "name": "pwsh", "cwd": "C:\\Projects\\AppTracker" }] },
  "browser_tab": { "url": "https://docs.rs/tokio", "title": "Tokio - Rust" }
}
```

### 场景二：效率统计

通过 ActivityStats 接口获取最近 60 秒的活动统计：

```json
{
  "window_seconds": 60,
  "keys_count": 342,
  "clicks_count": 28,
  "mouse_distance_px": 15234.5,
  "idle_seconds": 3.2
}
```

### 场景三：自动化触发

通过 WebSocket 监听 `window_changed` 事件，当检测到特定应用切换时自动执行动作：

```javascript
const ws = new WebSocket('ws://127.0.0.1:5007/api/v1/ws');
ws.onmessage = (e) => {
  const msg = JSON.parse(e.data);
  if (msg.type === 'window_changed' && msg.data.app_name === 'Slack') {
    // 自动打开日历提醒
  }
};
```

## 设计目标

1. **低资源消耗**：250ms 轮询间隔，CPU 占用极低
2. **跨平台一致性**：Windows/macOS/Linux 三平台统一 API
3. **隐私优先**：所有数据留在本地，不上传任何云端
4. **非侵入性**：不注入目标进程，不修改系统行为
5. **可扩展性**：模块化架构，易于添加新的采集源

## 与同类产品对比

| 特性 | AppTracker | RescueTime | ActivityWatch |
|------|-----------|------------|---------------|
| 开源 | 是（MIT） | 否 | 是（MPL） |
| 数据存储 | 本地 API | 云端 | 本地 + 可选同步 |
| 文档追踪 | 支持（Office/编辑器/文件管理器） | 仅应用级别 | 仅窗口标题 |
| 终端 cwd | 支持（18 种 Shell） | 不支持 | 不支持 |
| 浏览器标签页 | 支持（扩展桥接） | 内置 | 扩展 |
| 截图采集 | 可选 | 不支持 | 不支持 |
| API 方式 | REST + WS + SSE | REST | REST |
