## 简介

AppTracker 是一款跨平台桌面活动追踪器，能够实时监控前台窗口、打开的文档、终端工作目录、浏览器标签页以及键盘鼠标活动。本文档将引导您从零开始搭建开发环境并运行项目。

## 环境准备

### Rust 工具链

项目使用 Rust 2021 edition，建议通过 [rustup](https://rustup.rs/) 安装稳定版：

```bash
rustup default stable
```

### Node.js

桌面端 Tauri 应用需要 Node.js 18+：

```bash
node --version   # 确认 >= 18
npm --version
```

### 平台特定依赖

| 平台 | 依赖 |
|------|------|
| Windows | Windows SDK（Win32 API），PowerShell 5.1+ |
| macOS | Xcode Command Line Tools，Accessibility/Automation 权限 |
| Linux | `xdotool`、`xprop`、`xwininfo`；可选 `zbus`（AT-SPI） |

Linux 安装示例：

```bash
# Debian/Ubuntu
sudo apt install xdotool x11-utils
# Fedora
sudo dnf install xdotool xorg-x11-utils
```

## 项目获取

```bash
git clone <repository-url> AppTracker
cd AppTracker
```

工作区结构（Cargo workspace）：

```
AppTracker/
├── Cargo.toml          # workspace 根
├── tracker-core/       # 核心采集引擎 crate
├── desktop/            # Tauri 桌面应用
│   ├── src-tauri/      # Rust 后端（Tauri）
│   └── ui/             # 前端（vanilla HTML/CSS/JS）
├── browser_extension/  # Chrome/Firefox MV3 扩展
└── shell_integration/  # bash/zsh/fish/pwsh/cmd 钩子
```

## 构建与运行

### 方式一：Tauri 桌面应用（推荐）

```bash
cd desktop
npm install
npm run tauri dev
```

此命令会同时启动 Vite 前端开发服务器和 Tauri Rust 后端，弹出桌面窗口。

### 方式二：仅核心库

如果只需要 tracker-core 作为库集成到其他项目：

```bash
cd tracker-core
cargo build
cargo test
```

### 方式三：release 构建

```bash
cd desktop
npm run tauri build
```

产出物位于 `desktop/src-tauri/target/release/`。

## 首次启动验证

启动后，AppTracker 会在 `~/.apptracker/` 目录下创建配置：

- `token` — 浏览器扩展鉴权令牌（自动生成，base64 编码）

通过 API 验证服务是否正常：

```bash
curl http://127.0.0.1:5007/api/v1/health
# 期望输出: {"ok":true,"service":"apptracker"}
```

获取当前快照：

```bash
curl http://127.0.0.1:5007/api/v1/snapshot | jq
```

## 浏览器扩展安装

1. 打开 `browser_extension/` 目录
2. Chrome/Edge：进入 `chrome://extensions`，开启"开发者模式"，点击"加载已解压的扩展程序"，选择 `browser_extension/` 目录
3. Firefox：进入 `about:debugging`，点击"此 Firefox"，点击"临时载入附加组件"，选择 `manifest.json`
4. 在扩展弹窗中粘贴从 AppTracker UI 或 API 获取的 Token

扩展通过 WebSocket 连接到 `ws://127.0.0.1:5007/api/v1/browser`，自动上报活动标签页信息。

## Shell 集成配置

Shell 集成脚本通过在每次提示符显示时写入 `~/.active_tracker/shells/<PID>.cwd` 文件，让 AppTracker 能够获取终端的实时工作目录。

### Bash / Zsh

在 `~/.bashrc` 或 `~/.zshrc` 中添加：

```bash
source /path/to/AppTracker/shell_integration/bash.sh
```

### Fish

```fish
source /path/to/AppTracker/shell_integration/fish.fish
```

### PowerShell

在 PowerShell profile 中添加：

```powershell
. 'C:\path\to\AppTracker\shell_integration\powershell.ps1'
```

### cmd.exe

运行 `shell_integration/install_windows.cmd` 或手动在 AutoRun 注册表中添加。

## 常见问题

### 端口被占用

AppTracker 默认使用端口 5007，如果被占用会自动尝试 5008-5012。可在 UI 的 API 输入框中修改地址。

### macOS 权限问题

首次运行时系统可能弹出 Accessibility / Automation 权限请求。请在"系统设置 > 隐私与安全性 > 辅助功能"中授权 AppTracker。

### Linux Wayland 限制

Wayland 下通用前台窗口捕获能力受限。建议使用 X11 会话以获得完整功能。
